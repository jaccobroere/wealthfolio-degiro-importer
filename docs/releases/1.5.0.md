# DEGIRO Importer 1.5.0

## Highlights

- **Re-importing a full history only adds what is new.** DEGIRO exports are
  usually re-imported as a complete history on top of an earlier import.
  Previously that could add a second copy of most dividends and trades. The
  importer now compares every activity with the activities already on the
  destination account — on type, day, currency and value (quantity and trade
  value for buys and sells) — before anything is written, and skips the ones
  that are already there. Repeated identical rows, such as several fees on one
  day, are counted rather than collapsed.

- **Every trade and dividend is linked to its security.** Wealthfolio 3.6.1's
  import endpoint does not create securities. When a security did not exist
  yet, its activities were stored with no security at all: they moved cash but
  did not show up in holdings (they appear in the activity list with only a
  currency). On a later import, once the security existed, Wealthfolio no longer
  recognised them as duplicates, so linked copies were added next to them. The
  importer now creates a missing security by writing one of its activities
  through Wealthfolio's bulk activity API, then imports the rest linked to it.
  An activity whose security cannot be created is reported as failed; it is
  never stored without its security.

- **See what is already in Wealthfolio before importing.** The reconcile step
  has a new _Already in Wealthfolio_ section that shows how many activities are
  new, how many will be skipped, and lists account activities that need
  attention:
  - _extra copies_ — duplicates of an activity in this statement, usually left
    by an earlier import. Delete them in Wealthfolio.
  - _activities without a security_ — the only copy of an activity, stored
    unlinked by an earlier version. Delete them and run the import again to
    re-create them linked.

  The acknowledgement now states how many new activities will be written.

- **Repeated identical activities are all kept.** DEGIRO sometimes books the
  same dividend several times on one day, each time raising the balance.
  Wealthfolio's import keeps only one activity per day, security, amount and
  comment, so the other copies were silently dropped and cash came out short.
  The second and later copies now get a numbered comment (`Dividend #2`) and
  are imported. The first copy is unchanged, so it still matches earlier
  imports.

- **Correct cash for foreign-currency trades that create a security.**
  DEGIRO quotes its FX rate as trade currency per EUR; Wealthfolio reads an
  activity's FX rate the other way round. The activity that creates a new
  security no longer passes DEGIRO's rate, so its cash stays in the trade
  currency, as it does for every other imported activity.

- **Tickers in review and reconcile.** The review table and the net-position
  table show the Wealthfolio ticker and exchange you mapped each security to,
  with the statement's product name and ISIN underneath, instead of the ISIN
  alone.

## Permissions

This release adds `activities.saveMany`. It is used only to create securities
Wealthfolio does not know yet (one activity per new security). All other
activities still go through `activities.import`. The add-on never updates or
deletes existing activities.

## Compatibility

- Wealthfolio: 3.6.1
- Add-on SDK: 3.6.1
- DEGIRO account-statement CSV exports in Dutch or English header variants
