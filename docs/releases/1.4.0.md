# DEGIRO Importer 1.4.0

## Highlights

- **Fix problem rows in the review step, without editing your CSV.** Any row
  in the review table now expands into per-row reviewer controls. A row can be
  **edited** — correct the description, amount, ISIN, date or any other source
  field, with a live preview of exactly what the pipeline will do with the
  corrected row — or **ignored**, which excludes it from the import. Previously
  a single unrecognized row meant editing the source file by hand and starting
  the import over.

  Both actions are deliberate, per-row, and fully accounted for: an ignored row
  becomes a `user-ignored` known-skip rather than disappearing, so the
  every-source-row-has-exactly-one-outcome invariant still holds and the count
  stays visible in the review and reconcile summaries. Activities built from an
  edited row carry a warning, and the reconcile step shows how many rows you
  changed before you acknowledge. Nothing is ever written back to your CSV.

- **`Inkomsten uit Securities Lending` is now recognized.** DEGIRO's monthly
  securities-lending revenue share was previously an unrecognized row that
  blocked the whole import. It now maps to an `INTEREST` activity, like
  `Flatex Interest`.

- **Row conservation hardened in order-group mapping.** Three paths could
  previously leave a grouped row with no outcome at all, silently breaking the
  conservation invariant and hiding the row from the review table: an order
  group with no parent trade dropped its `Meegekochte Rente` rows, a group whose
  fills summed to zero quantity dropped everything but the trade rows, and a
  positive (reversal) in-group `Transactiebelasting` row was dropped entirely.
  The last of these was reachable with no reviewer overrides involved. All
  group mapping now exits through a single guard that guarantees every input row
  leaves with either a membership or a skip.

- **A large, realistic regression fixture.** `tests/fixtures/degiro-realistic-statement.csv`
  is a 200-row fully synthetic statement shaped like a real multi-year export
  (reverse-chronological, Dutch-locale decimals, EUR + USD ledgers, grouped and
  ungrouped trades, and the full breadth of broker-bookkeeping noise). Its
  golden test asserts exact outcome counts, per-ledger running-balance
  integrity, and fingerprint stability, so contributors and CI finally have a
  realistic conservation gate that does not require a private statement.

## Compatibility

- Wealthfolio: 3.6.1
- Add-on SDK: 3.6.1
- DEGIRO account-statement CSV exports in Dutch or English header variants

No migration is required. Activities imported by earlier versions keep their
fingerprints; an edited row produces a different fingerprint only when its
economic values actually change, which is the intended behaviour.

## Validation gap (honest disclosure)

The `pnpm release:check` gate was **not** run in full for this release. The
standard `pnpm check` (format, lint, type-check, 179 unit tests, fixture
privacy scan, build, manifest validation) passed green, and the real private
statement was re-verified through `pnpm inspect:csv` (1175 rows: 0 unsupported,
0 invalid, 0 unaccounted, 0 fingerprint collisions). Not run: the
`DEGIRO_ACCEPTANCE_BASELINE` acceptance comparison (the reviewed baseline JSON
is private and was not available) and the disposable-host `pnpm test:host`
Playwright suite. Users importing real statements on this version are
encouraged to spot-check a recent statement before bulk-importing, and to look
carefully at the reconcile-step summary of any rows they ignored or edited.
